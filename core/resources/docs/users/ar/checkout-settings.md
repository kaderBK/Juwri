# إعدادات إتمام الطلب والضريبة والإكراميات

كل ما يراه الزبون عند إتمام الطلب — أي أنواع الطلبات يمكنه اختيارها، وهل
يظهر سطر ضريبة ومطالبة إكرامية، وكيف يمكنه الدفع — يُتحكَّم فيه لكل مطعم على
حدة. تستعرض هذه الصفحة تلك الإعدادات وتوضّح بدقة كيف يغيّر كل منها الإجماليات
التي تُحصَّل من عملائك.

## أين توجد هذه الإعدادات

افتح **المتاجر** في الشريط الجانبي، وحرّر مطعمًا، واستخدم شريط التبويبات
في أعلى الصفحة. تبويبان مهمّان هنا:

- **الطلبات** — أنواع الطلبات، ورسوم التوصيل، والحد الأدنى للطلب، والضريبة،
  والإكراميات، والكوبونات، والجدولة، وخيار عرض العملات المتعددة.
- **المدفوعات** — بوابات الدفع لكل مطعم ومفاتيح API الخاصة بها.

ينطبق كل إعداد في هذين التبويبين على ذلك المطعم الواحد فقط، لذا يمكن أن يكون
لمطاعم مختلفة في حسابك معدّلات ضريبة وإكراميات وبوابات مختلفة.

## أنواع الطلبات

تتحكم ثلاثة مفاتيح في تبويب **الطلبات** في أنواع الطلبات التي يمكن للزبائن
اختيارها عند إتمام الطلب:

- **الطلب من الطاولة** — يُدخل الزبون رقم طاولة. وعند مسحه رمز QR الطاولة
  يُملأ الرقم له.
- **طلبات الاستلام** — يُدخل الزبون رقم هاتف.
- **طلبات التوصيل** — يُدخل الزبون رقم هاتف وعنوانًا.

لا تظهر كأزرار في نموذج إتمام الطلب إلا الأنواع المفعّلة. وإذا كانت الثلاثة
كلها مُطفأة (أو كانت باقتك لا تتضمن الطلب)، تصبح القائمة للعرض فقط.

يوجد حقلان مرتبطان أسفل المفاتيح مباشرة:

- **رسوم التوصيل** — مبلغ ثابت يُضاف إلى إجمالي طلبات التوصيل فقط. ولا
  يُحصَّل أبدًا على طلبات الطاولة والاستلام.
- **الحد الأدنى لقيمة الطلب** — يُحظَر إتمام الطلب حتى يبلغ مجموع الأصناف الفرعي
  هذا المبلغ. اضبطه على 0 للتعطيل.

في هذا التبويب أيضًا: يتيح لك **المتجر مفتوح** و**Prevent orders when
closed** إيقاف الطلبات الجديدة دون إلغاء نشر القائمة، وإذا كنت تستخدم
[الفروع](branches.md)، يرفض الفرع المغلق الطلبات برسالة الإغلاق الخاصة به
بغض النظر عن هذه الإعدادات.

## الضريبة

تتحكم ثلاثة حقول في تبويب **الطلبات** في الضريبة:

- **نسبة الضريبة** — النسبة الضريبية. تُطبَّق على مجموع الأصناف الفرعي (الأصناف
  والمتغيرات والإضافات)، وتُقرَّب إلى منزلتين عشريتين، وتُضاف إلى الإجمالي.
  اضبطها على 0 لعدم وجود سطر ضريبة.
- **تسمية الضريبة** — الاسم المعروض على سطر الضريبة في السلة، مثل "VAT" أو
  "GST". والافتراضي "Tax". (تستخدم قوالب القائمة الأحدث هذا الوسم؛ أما
  الأقدم فتعرض سطر "Tax" عامًا.)
- **نوع الضريبة** — محدد نسبة مئوية/ثابت. حاليًا تُحسَب إجماليات الطلبات دائمًا
  كنسبة مئوية، لذا اترك هذا مضبوطًا على **نسبة مئوية**؛ إذ يُحفَظ خيار
  Fixed لكنه لا يُطبَّق على الإجماليات بعد.

تنطبق النسبة الضريبية على مجموع الأصناف الفرعي فقط — فلا تُفرَض ضريبة على
رسوم التوصيل والإكرامية. والإجمالي الكامل الذي يُحصَّل من الزبون هو:

    مجموع الأصناف الفرعي + رسوم التوصيل + الضريبة + الإكرامية − خصم الكوبون

يعيد الخادم حساب هذا الإجمالي بنفسه عند تقديم الطلب، فيطابق المبلغ المُحصَّل
دائمًا التفصيل المعروض في السلة.

## الإكراميات

فعّل **الإكراميات** في تبويب **الطلبات** للسماح للزبائن بإضافة إكرامية عند إتمام
الطلب. عند التفعيل، يعرض نموذج إتمام الطلب أزرارًا جاهزة — **10٪ و15٪
و20٪** من مجموع الأصناف الفرعي — إضافةً إلى خيار **مخصص** حيث يكتب الزبون
مبلغًا دقيقًا. والأزرار الجاهزة ثابتة ولا يمكن تغييرها حاليًا.

تُعرَض الإكرامية كسطر خاص بها في تفصيل السلة، وتُضمَّن في الإجمالي، وتُخزَّن
على الطلب — وتعرضها [صفحة الطلبات](orders.md) بجوار إجمالي الطلب. وتدعم
قوالب القائمة الحديثة الإكراميات (Aurora وPulse وVivid وCrave وGlow
وMatcha)؛ أما القوالب الأقدم فتتجاهل الإعداد.

## الدفع الإلكتروني والبوابات

يضيف مفتاح **الدفع عبر الإنترنت** في تبويب **الطلبات** خيار "Pay online" عند
إتمام الطلب (يجب أيضًا أن يكون مسؤول المنصة قد فعّل المدفوعات الإلكترونية على
مستوى الموقع). يُعاد توجيه الزبائن الذين يختارونه إلى صفحة دفع آمنة تسرد
بواباتك المفعّلة؛ ويظل الطلب مخفيًا عن قائمة طلباتك حتى يُدفَع.

هيّئ البوابات في تبويب **المدفوعات**. لكل بطاقة بوابة حالة (On/Off)، وعنوان
عرض، وحقول مفاتيح API الخاصة بها، و— حيث يدعم المزود ذلك — وضع اختبار
(sandbox). وتُخزَّن المفاتيح لكل مطعم. البوابات المتاحة: PayPal وStripe
وRazorpay وMollie وPaddle وPaytm وPaystack وPayUmoney وIyzico وMidtrans
وPayTabs وTelr و2Checkout وCCAvenue وTap (منطقة الشرق الأوسط وشمال أفريقيا)
وFlutterwave (أفريقيا) وTDSP / T-Lync (ليبيا) والتحويل البنكي. يعيد Paddle
التوجيه إلى صفحة دفع مستضافة من Paddle (وضع sandbox مدعوم). ويوسم التحويل
البنكي المعاملة بأنها معلّقة ويعرض تفاصيل بنكك؛ وتؤكّد الاستلام يدويًا.

يمكن للزبائن دائمًا اختيار الدفع عند المنضدة أو عند التوصيل بدلًا من ذلك —
إذ يُعرَض الدفع الإلكتروني إلى جانب النقد، لا بدلًا منه.

## مرجع البوابات — ما يطلبه كل منها

لكل بطاقة بوابة الحقلان الأولان نفسهما — **الحالة** (On/Off) و**العنوان**
(الاسم الذي يراه الزبائن) — إضافةً إلى مفتاح **sandbox** حيث يكون للمزود
وضع اختبار. القائمة أدناه هي حقول الاعتماد فوق تلك فقط. أدخلها تمامًا كما
تسمّيها لوحة تحكم المزود نفسها.

| البوابة | حقول الاعتماد | Sandbox |
|---|---|---|
| PayPal | Client ID, Secret, App ID | نعم |
| Stripe | Publishable key, Secret key | يستخدم مفاتيح اختبار |
| Razorpay | API key, Secret key | يستخدم مفاتيح اختبار |
| Mollie | API key | يستخدم مفتاح اختبار |
| Paddle | API key (Paddle Billing) | نعم |
| Paytm | Merchant key, Merchant MID, Merchant website | نعم |
| Paystack | Secret key, Public key | يستخدم مفاتيح اختبار |
| PayUmoney | Merchant POS ID, Signature key, OAuth client ID, OAuth client secret | نعم |
| Iyzico | API key, Secret key | نعم |
| Midtrans | Client key, Server key | نعم |
| PayTabs | Region, Profile ID, Secret key | حسب المنطقة |
| Telr | Store ID, Auth key | نعم |
| 2Checkout | Account number, Public key, Private key | نعم |
| CCAvenue | Merchant key, Access code, Working key | لا |
| Tap (منطقة الشرق الأوسط وشمال أفريقيا) | Secret key, Publishable key | نعم |
| Flutterwave (أفريقيا) | Secret key, Public key | نعم |
| TDSP / T-Lync (ليبيا) | Store ID, Token | نعم |
| Paylink / STC Pay (السعودية) | API ID, Secret key | نعم |
| Paymob (السعودية / مصر) | Secret key, Public key, Integration ID, HMAC secret | نعم |
| Geidea (السعودية) | Merchant public key, API password | نعم |
| Fawry (مصر) | Merchant code, Security key | نعم |
| Fatora (قطر) | API key | نعم |
| Noon Payments (السعودية) | Business ID, Application ID, API key, Webhook secret | نعم |
| Tamara (اشترِ الآن وادفع لاحقًا) | API token, Notification token | نعم |

| Wire Transfer | نص تفاصيل البنك (لا مفاتيح API) | — |

ملاحظات على بعضها:

- **تحويل بنكي** لا يأخذ أي مفاتيح إطلاقًا. يوسم المعاملة بأنها معلّقة
  ويعرض تفاصيل البنك التي تكتبها؛ وتؤكّد الاستلام بنفسك.
- **Noon** له سر ويب هوك منفصل لأن noon توقّع استدعاءاتها المرتجعة؛ اتركه
  فارغًا فلا يمكن التحقق من تلك الاستدعاءات.
- **Paymob** يحتاج كذلك إلى سر HMAC للتحقق من الاستدعاءات المرتجعة.
- **CCAvenue** ليس له مفتاح sandbox هنا — استخدم حساب التاجر التجريبي الخاص
  بـ CCAvenue.
- **GoCardless** و**Lemon Squeezy** يهيّئهما مسؤول المنصة فقط، لا لكل مطعم.
  يأخذ GoCardless رمز وصول وسر ويب هوك؛ ويأخذ Lemon Squeezy مفتاح API
  ومعرّف متجر ومعرّفات متغيرات وسر ويب هوك، مع مفتاح وضع اختبار.

تصل استدعاءات المزود المرتجعة على روابط منصة مشتركة — `/ipn/{gateway}`
و`/webhook/{gateway}` — لذا حيث يطلب مزود رابط إشعار، استخدم تلك مع اسم
البوابة نفسه. ولست بحاجة إلى تهيئتها لكل مطعم.

## اشترِ الآن وادفع لاحقًا (Tabby وTamara)

Tabby وTamara بوابتا تقسيط ولهما بوابة إضافية فوق On/Off المعتادة، في تبويب
**الطلبات**:

- **Enable BNPL** — مفتاح رئيسي. عند إطفائه، لا تُعرَض أي من بوابتَي BNPL
  عند إتمام الطلب حتى لو كانت بطاقتها On.
- **الحد الأدنى للسلة** — لا يظهر BNPL إلا عندما يبلغ إجمالي الطلب هذا المبلغ.
  والافتراضي **200** إذا تركته فارغًا. وهو رقم بسيط بعملة قائمتك؛ ويظل
  المزود يفرض حده الأدنى الحقيقي بعملته فوق ذلك.

فلا يظهر خيار BNPL للزبون إلا عند تحقّق الثلاثة معًا: البوابة مثبَّتة لذلك
المطعم، وBNPL مفعّل، والإجمالي عند الحد الأدنى أو فوقه. أما مدفوعات
الاشتراك وشحن المحفظة والعضوية فتتخطّى عتبة السلة تمامًا — إذ يكون مفتاح
البوابة على مستوى المنصة هو الشرط الوحيد هناك.

## Apple Pay وGoogle Pay

تعتمد مدفوعات المحافظ على Stripe:

- **عبر صفحة دفع Stripe (يعمل اليوم).** تستخدم مدفوعات الطلبات عبر Stripe
  صفحة الدفع المستضافة من Stripe، التي تعرض Apple Pay وGoogle Pay تلقائيًا
  على الأجهزة المدعومة بمجرد تفعيلك للمحافظ في لوحة Stripe لديك. ولـ Apple
  Pay يجب أيضًا إتمام التحقق من النطاق في Stripe للنطاق الذي تُقدَّم منه
  قائمتك — تقدّم المنصة ملف التحقق المطلوب بمجرد وضع مضيفك له، لذا اسأل
  مسؤول منصتك إذا فشل التحقق.
- **زر المحفظة داخل الصفحة (مخطَّط، غير متاح بعد).** زر Apple/Google Pay
  بنقرة واحدة يظهر مباشرة على القائمة مبنيٌّ في جانب الخادم لكنه لا يُعرَض
  بعد على أي قالب قائمة، فلن يراه الزبائن بعد.

يحسب المساران مبلغ الرسوم في الخادم من الطلب، لا من المتصفّح أبدًا، فلا
يمكن لصفحة مُلاعَب بها تغيير ما يُحصَّل.

## عرض العملات المتعددة

ضمن **المتاجر ← تعديل ← اللغات والعملة** يمكنك عرض أسعار تقريبية بعملات
أخرى للسياح:

1. اضبط **إظهار الأسعار بعملات متعددة** على Yes.
2. أدخل **Manual exchange rates**، واحدًا في كل سطر، بصيغة `CODE=rate` —
   مثلًا `EUR=0.92` يعني أن وحدة واحدة من عملة قائمتك تساوي 0.92 يورو.

يظهر عندئذٍ مبدّل عملات صغير على القائمة (تدعمه قوالب Aurora وNebula
وPulse وCrave وGlow وMatcha). وهذا للعرض فقط: تحمل الأسعار المحوّلة إخلاء
مسؤولية ("Prices shown in EUR (approximate). Charged in base currency.")
وتستخدم السلة وإتمام الطلب والرسوم الفعلية دائمًا عملة قائمتك الحقيقية. ولا
تُحدَّث المعدّلات تلقائيًا — راجعها بين الحين والآخر. ولا توجد تغذية معدّلات
صرف تلقائية؛ فالمعدّلات اليدوية هي المصدر الوحيد.

## استمرارية السلة

لا شيء لتهيئته هنا — فهي تلقائية. تُحفَظ سلة الزبون على جهازه الخاص، على حدة
لكل مطعم، فإغلاق المتصفّح أو تبديل التطبيقات لا يفقده طلبه. على قوالب Aurora
وNebula وVivid يرى الزبون العائد لافتة "resume your order" تعرض عليه
استعادة السلة المحفوظة أو مسحها؛ وعلى تلك القوالب تنتهي صلاحية السلال
المحفوظة بعد 24 ساعة، وتُسقَط الأصناف التي نفدت أو أُزيلت من القائمة منذ ذلك
الحين تلقائيًا قبل استعادة السلة. أما القوالب الأخرى فتستعيد السلة المحفوظة
بصمت دون لافتة.
