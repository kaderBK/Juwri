# User guide for restaurant owners

This is the task-based guide for restaurant owners and their staff — the people
who run the dashboard day to day. It covers building your menu, sharing it,
taking and cooking orders, running the floor, managing your team, growing your
customer base, and looking after your account. Each page explains where a
feature lives in the dashboard, the steps to use it, and any limits that apply.
Pages are written against the live dashboard theme; where a feature is specced
but not yet built, the page says so plainly.

New here? Start with [Getting started](getting-started.md), then
[Dashboard overview](dashboard-overview.md).

## Coverage gaps

A few features have working backends but no way to reach or finish them from
the dashboard yet. The relevant pages flag these as planned or not-yet-available:

- **Built but not reachable from the UI.** Adding a reservation by hand or
  assigning a table on the [reservations](reservations.md) page, switching the
  [KDS](kds.md) between basic and advanced mode or firing a course, staff
  claiming or swapping open shifts from the [staff app](staff-app.md), and
  per-item [modifier](modifiers.md) price/quantity overrides all exist
  server-side but have no control in the dashboard. The item-level KDS bump/recall
  board is only in the [staff app](staff-app.md), not on the desktop board. (POS
  voids, refunds, the Z-report, split payments, tips and discounts, and per-branch
  printer routing — previously endpoint-only — now all have dashboard controls;
  see [POS](pos.md) and [printing](printing.md).)
- **Not wired to the storefront everywhere.** Diner per-item reviews and the
  [AI chat widget](ai-agents.md) render on all 17 modern menu themes (see the
  [theme capability matrix](theme-capability-matrix.md)), but not on the legacy
  templates (classic, modern, orange, …) that many stores still run, so those
  diners see no rating form or chat bubble. There is no in-page Apple Pay /
  Google Pay button at [checkout](checkout-settings.md) on any theme.
- **Printing.** There is still no cloud printing (e.g. PrintNode); direct
  USB / RawBT / network-bridge printing and per-branch / per-station routing
  with copy counts are built ([printing](printing.md)), but the Orders-page
  "auto-print" toggle itself still only refreshes the list — unattended
  auto-print runs through the print profiles, not that toggle.
- **Specced but not built.** Delivery zones and delivery radius
  ([delivery](delivery.md)), live card processing / terminal charging in the
  [POS](pos.md), by-item (per-seat) [splitting](split-bill.md), and an
  owner-facing NPS report ([reviews](reviews-feedback.md)) are all planned only.
- **Known issues to be aware of.** Server-side
  enforcement of a delivery minimum order value and of day-of-week item
  availability is not in place; those are enforced (if at all) in the storefront.
  (An earlier issue where an owner's own [coupon](coupons.md) previewed in the
  cart without discounting the charged total has been fixed — owner coupons now
  apply to the final total, including free-delivery codes.)
