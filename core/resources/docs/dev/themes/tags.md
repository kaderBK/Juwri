# Custom Liquid tags

GENERATED by `docs:build-reference` from the engine's tag registrations — do not edit by hand.
Standard Liquid core tags also work.

## {% commerce %} (inline)
Syntax: `{% commerce %}`

Emits the platform commerce runtime (cart/checkout config + versioned commerce.js, CSP-nonced) exactly once per page — repeat uses emit nothing. Takes no arguments. Place once in the layout; themes never call ordering APIs directly.

Example:
```liquid
{% commerce %}
```

## {% schema %} (block)
Syntax: `{% schema %} { ...JSON... } {% endschema %}`

Section/settings schema block. The JSON body is parsed and validated at upload time (invalid JSON is a syntax error) and emits NOTHING at render — it is metadata for the theme editor. Body is raw: Liquid inside is not executed. At most one per section file; values reach the template via section.settings.

Example:
```liquid
{% schema %}
{
  "name": "Hero",
  "settings": [
    { "type": "text", "id": "heading", "label": "Heading", "default": "Welcome" }
  ]
}
{% endschema %}
```

## {% widget %} (inline)
Syntax: `{% widget 'name' %} or {% widget 'name', label: 'Text' %}`

Renders an allow-listed platform widget — a trigger button plus its own accessible dialog, CSP-nonced JS and --tc-* token styling — for features that need server logic: reservation, waitlist, catering, loyalty, store-reviews, branch-switcher. The name must be a quoted literal; an unknown name is a syntax error at upload (and renders nothing live). Renders nothing when the store has the feature switched off (the same gate as `features.*`), so it is safe to place unconditionally. Only `label` is accepted as a parameter. Repeat uses keep every trigger but write the dialog once.

Example:
```liquid
{% widget 'reservation' %}
{% widget 'loyalty', label: section.settings.loyalty_label %}
```
